# Our Living Legacy: recoverable shared original audio

Authority: the owner's full MVP v0.5 scope and request to continue independently; V2 D02; the private-session boundary decision of 2026-11-13. This implements I-02–I-10, I-17–I-19 and I-25 without changing Foundation promises.

For an in-person two-person conversation, one shared microphone is an acceptable original. Capture requires the host and both current, versioned participant recording decisions. The server pins the photograph, consent epoch and the two current consent events before requesting the microphone. Browser permission is contextual; readiness is rechecked after permission resolves. Different people operating guest/host capabilities are not claimed as verified identities.

The browser keeps original recorder chunks in a separate IndexedDB database, serializes writes and uses a native Web Lock for each active take. A second tab cannot finalize an active recorder's partial prefix. A terminated page releases its lock; recoverable chunks reopen as an explicitly partial recording. Pause/resume uses the same encoder. Reload does not concatenate independent encoder runs. Missing trailing chunks are never described as recovered. Capture stops on withdrawn consent, access/connection loss, hidden page, recorder/track failure, or device-storage failure. A photograph stays visible beside recording and replay controls.

Storage-full recovery retains available bytes in memory and holds the take lock while that page is open; the user is told to keep the page open and back up. This is not a promise of reload durability for bytes that could not be written. Native locks/BroadcastChannel and recoverable device storage are capability requirements for this conversation recorder; unsupported browsers receive a clear error without requesting the microphone.

Private R2 stores a distinct immutable session original. Bounded uploads verify actual bytes, signature, checksum and client-reported duration. Conditional writes and independent R2 head evidence precede D1 durable confirmation. Retries use the same source identity. A final transactional consent check rejects changed epochs; later re-consent does not authorize an earlier unconfirmed capture. Unconfirmed objects remain private pending repair or deliberate whole-memory deletion. Withdrawal alone does not invent a legal retention/deletion policy or erase an earlier accepted source.

Whole-memory deletion marks related sessions unavailable before storage cleanup, denies new capture/access, removes pending/durable recording objects and cascades notes/provenance. A late upload checks that deletion state and removes its unconfirmed object. Client deletion also signals other tabs, stops capture, waits for the take lock and removes matching device records/chunks. A device-cleanup failure is reported separately and can be retried after the remote record is already gone. As with existing originals, arbitrary external copies cannot be recalled.

The shared track remains speaker-unconfirmed outside sections each participant identifies as their own. A participant can add an immutable self-attributed time range and optional separate recollection. The host cannot submit another participant's attribution. These human notes are additive; they never replace audio, become a machine transcript, or reconcile differing accounts. Replay is scoped to authorized session participants and supports byte ranges.

The configured ten-minute recording bound is an implementation guard, not a settled paid offer. No automatic publication, video provider, transcription, live deployment or final consent/retention policy is activated by D02. Remote two-person media is the next slice. Physical/uncoached family acceptance remains deferred to the owner-requested milestone.
