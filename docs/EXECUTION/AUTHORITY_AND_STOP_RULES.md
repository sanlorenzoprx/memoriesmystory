# Campaign Authority and Stop Rules

## Authorized without another product decision

- Implement Packets 1–8 within the approved Phase 1 specification.
- Change source, tests, migrations, safe configuration, implementation docs, receipts, and learning records in the canonical repository.
- Install normal project dependencies with reviewed lockfile changes.
- Generate synthetic fixtures and local development secrets that remain ignored.
- Provision isolated staging resources after a redacted credential/account preflight.
- Run minimal staging Workers AI transcription evidence in English and Spanish or mixed language.
- Create bounded commits and publish campaign branches.

## Requires owner approval

- production deployment, public launch, DNS or traffic changes;
- billing activation, paid plan upgrades, or a recurring-spend commitment;
- destructive or irreversible data operations;
- final legal language;
- widening scope beyond Phase 1;
- weakening or changing a locked Foundation promise;
- selecting a paid transcription fallback without evidence;
- sending real family media to a new provider.

## Stop and escalate when

- a required credential is missing at the packet that owns it;
- a source conflicts with a higher-authority document;
- the same material failure repeats twice after a scoped fix;
- a test must be weakened or skipped to claim completion;
- privacy, ownership, durable-save truth, or immutable originals cannot be proven;
- a provider requires unapproved data handling or spend;
- production state would be affected;
- more than one implementation packet would need to be active to proceed.

## Safety defaults

No secret values in Git or receipts. No raw provider responses or family media in logs. No live production action as validation. No silent scope expansion. No claim of completion from mock-only evidence.
